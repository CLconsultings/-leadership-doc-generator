## Rule

The repository state at the protected baseline is the controlling starting point for subsequent skill layering.

Newer skill content may be added when it is additive, clarifying, or extends capability without reversing a prior repository decision. Existing files, framework names, approved template assets, production mechanics, corrections, tests, and prior authored language must not be silently replaced by a later skill import.

When newer skill content conflicts with the protected baseline:

1. preserve the protected baseline behavior;
2. record the newer material as a proposed or supplementary layer only when it remains useful;
3. surface the conflict for an explicit Leadership-Link decision before changing the controlling behavior;
4. never use an automated import to rewrite proprietary framework language or approved production assets.

- Existing repository content = locked foundation.
- New files = additive layer.
- Existing file edits = append or route to additive material while preserving prior instructions unless an explicit approved change says otherwise.
- Binary assets and the approved PowerPoint template remain untouched by text-layer imports.
