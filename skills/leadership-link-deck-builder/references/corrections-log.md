# Corrections Log and release standard

This file holds two things that must both be retained: the Corrections Log and the
"What Great Looks Like" release standard. Calibration examples support judgment but do
not replace either of these.

Apply the Corrections Log internally on every deck. Never expose it in client-facing
work.

## What Great Looks Like (release standard)

A successful output:

- reflects Eileen's actual reasoning
- names the real leadership tension
- produces practical behavioral guidance
- preserves approved framework language
- distinguishes verified content from inference
- protects client confidentiality
- uses the approved Leadership-Link design system
- remains editable
- includes useful speaker notes
- is visually clean and presentation-ready
- contains no invented curriculum
- does not rely on generic leadership language

A polished output that violates framework fidelity is not acceptable. An incomplete
output that clearly identifies a source gap is preferable to a complete-looking
fabrication.

## Corrections Log

Record each confirmed correction as an entry. When a correction is confirmed: record the
failed behavior, record the required behavior, generalize the lesson only when
appropriate, and use the entry to prevent the same failure in future output.

Use this format for each entry:

```
### YYYY-MM-DD: short title
- Context: what was being produced
- Failed behavior: what went wrong
- Required behavior: what should happen instead
- Generalized lesson: the broader rule, if one applies (omit if the fix is specific)
- Status: active
```
